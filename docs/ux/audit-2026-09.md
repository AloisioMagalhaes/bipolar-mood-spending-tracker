# Auditoria UX/UI — 2026-09

Auditoria baseada na inspeção da GitHub Page e do código público. Esta entrega corrige a primeira camada de publicação e deixa o backlog visual rastreável; não constitui validação clínica.

## Achado crítico

A Page publicada apresentava uma tela branca e nenhuma aplicação na árvore de acessibilidade. O workflow de Pages fazia build/deploy, mas não verificava se o conteúdo renderizava após o deploy.

## Mudanças desta entrega

- `web/index.html` agora tem título, descrição, loading shell acessível, aviso de JavaScript e remoção do shell no primeiro frame Flutter.
- `.github/workflows/pages.yml` agora executa smoke test Playwright em viewport móvel após o deploy.
- `docs/github-project-template.md` define views, campos, labels e automações reproduzíveis no GitHub Projects.

## Próximo backlog UX/UI

1. onboarding curto com consentimento informado;
2. painel “Hoje” com as três ações primárias;
3. estados vazio, erro, offline, salvamento e desfazer;
4. equivalentes textuais para visualizações temporais;
5. auditoria manual de teclado, leitor de tela, zoom e contraste;
6. budget de performance Web e teste em rede limitada.

## Critérios de aceite

- a URL de Pages renderiza `MoodLedger` ou `Seu acompanhamento` em até 5 s;
- a tela inicial não exige rolagem horizontal em 320 dp;
- toda informação gráfica relevante possui texto/semantics;
- deploy falha quando o smoke test não encontra conteúdo esperado;
- nenhum texto sugere diagnóstico ou causalidade.
